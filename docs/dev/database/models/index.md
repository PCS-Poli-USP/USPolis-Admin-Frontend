# Tabelas, Modelos e Relacionamentos

O banco tem hoje **50 tabelas**, uma para cada classe `SQLModel` com `table=True` em `server/models/database/` (mais as tabelas de ligação N:N, que também são um arquivo cada). Esta página lista todas elas, agrupadas por domínio. "Campos principais" omite `id` (toda tabela tem, exceto as com chave composta, indicadas em cada seção) e os timestamps padrão (`created_at`/`updated_at`, quando existem).

## Usuários, papéis e permissões

| Model — tabela                                                                           | Campos principais                                                                                                               | Relacionamentos                                                                                                                                                                                                                                                                      |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `User` — `user`                                                                          | `email` (único), `is_admin`, `name`, `last_visited`, `receive_emails` (padrão `True`), `active` (padrão `True`), `picture_url?` | `created_by: User` (autorreferência — quem criou essa conta), `curriculum: Curriculum?`, `current_schedule: UserSchedule?`, N:N com `Building` (`userbuildinglink`), `Group` (`groupuserlink`) e `Role` (`userrole`); 1:N com `Reservation`, `Solicitation`, `Feedback`, `BugReport` |
| `Role` — `role`                                                                          | `name`, `description`, `resources: list[Resource]` (array de enum)                                                              | N:N com `User` (`userrole`); 1:N com `BuildingPermission`, `ClassroomPermission`, `CoursePermission`                                                                                                                                                                                 |
| `UserRole` — `userrole`                                                                  | vínculo `user_id` + `role_id` (únicos juntos), `granted_by_id`, `granted_at`                                                    | liga `User` a `Role`                                                                                                                                                                                                                                                                 |
| `BasePermission` _(abstrata, sem tabela própria)_                                        | `role_id`, `granted_by_id`, `granted_at`                                                                                        | campos herdados por toda `*Permission` abaixo                                                                                                                                                                                                                                        |
| `BuildingPermission` — `buildingpermission`                                              | `building_id?`, `actions: list[BuildingAction]`                                                                                 | `role`, `granted_by: User`, `building: Building?`                                                                                                                                                                                                                                    |
| `ClassroomPermission` — `classroompermission`                                            | `classroom_id?`, `actions: list[ClassroomAction]`                                                                               | `role`, `granted_by: User`, `classroom: Classroom?`                                                                                                                                                                                                                                  |
| `CoursePermission` — `coursepermission`                                                  | `course_id?`, `actions: list[CourseAction]`                                                                                     | `role`, `granted_by: User`, `course: Course?`                                                                                                                                                                                                                                        |
| `Group` — `group`                                                                        | `name`, `building_id` (único junto com `name`)                                                                                  | `building: Building`; N:N com `Classroom` (`groupclassroomlink`) e `User` (`groupuserlink`)                                                                                                                                                                                          |
| `UserBuildingLink` / `GroupUserLink` / `GroupClassroomLink`                              | tabelas de ligação, só as duas FKs compostas como PK (`ON DELETE CASCADE`)                                                      | —                                                                                                                                                                                                                                                                                    |
| `UserSession` — `usersession` _(PK própria: `id: str`, um UUID hex, não autoincremento)_ | `user_id`, `user_agent`, `ip_address`, `expires_at`                                                                             | `user: User`. Veja o ciclo de vida completo (renovação deslizante de 30 dias, teto de 90) no `SESSION_MANAGEMENT.md` do backend e em [Backend › Autenticação](/dev/backend#autenticação)                                                                                             |

> [!WARNING]
> Existem **duas** camadas de controle de acesso convivendo no banco: o vínculo direto por prédio/grupo (`userbuildinglink`, `groupuserlink`) e o sistema baseado em `Role` acima. Veja [Banco de Dados › Sistema de permissões](/dev/database#sistema-de-permissões).

## Estrutura acadêmica (prédios, salas, disciplinas, cursos)

| `Course` — `course`                                                             | `name` (único), `minimal_duration`, `ideal_duration`, `maximal_duration`, `period`, `created_by_id`, `updated_by_id`                                                                                        | 1:N com `Curriculum` (cascade delete)                                                                                                                           |
| `CourseOptions` — `courseoptions` _(sem `id`; PK composta `codcur` + `codhab`)_ | `name`                                                                                                                                                                                                      | tabela de apoio (opções de curso/habilitação vindas do Jupiter/Janus), sem relationship declarado                                                               |
| `Curriculum` — `curriculum` (grade curricular)                                  | `codcur` + `codhab` (únicos juntos), `course_id` + `description` (também únicos juntos), `AAC`, `AEX`                                                                                                       | `course: Course`; 1:N com `CurriculumSubject` (cascade delete) e `User` (usuários vinculados àquele currículo)                                                  |
| `CurriculumSubject` — `curriculumsubject`                                       | `curriculum_id` + `subject_id` (únicos juntos), `type`, `category`, `period`                                                                                                                                | `curriculum`, `subject`                                                                                                                                         |

> [!TIP]
> `Building` já teve um typo em `server/models/database/building_db_model.py` (`__table__args__`, com dois underscores extras, em vez de `__table_args__`) que fazia o SQLAlchemy ignorar silenciosamente esse atributo — a `UniqueConstraint` sobre `main_group_id` nunca era aplicada no banco de fato. Isso foi corrigido, com a migração correspondente (`unique_main_group_id`) adicionando a constraint que já deveria existir.
